# Spec changes after S17

This list helps an implementer find what the specs now ask for and the code does not yet do. The
specs are the source. This list only groups the work into slices. Open one pull request for each
slice, with an end-to-end test.

## Behaviour that changes

These are in the code today and the specs now say something else.

| Spec | Before | Now |
| --- | --- | --- |

| 003 | The working line reads "Working…". | It reads "Working…" or a playful phrase, and names a routine for a routine run. |

| 000, 014 | The exceptions are the model providers, the pages and the decision model. | One more exception: connections that the user adds on purpose (018). They get data only when an agent calls one of their tools. |

| 007 | No record of what the tools did. | An action log of file, shell, web and connection steps, kept for 90 days and at most 100000 entries. |
| 009 | No limit on routines, and a routine that fails keeps running. | At most 50 routines. A note for a schedule under 15 minutes. A routine pauses after 3 failed runs in a row. |
| 003 | The command list shows commands and runtime skills. | It also shows the skills that the user saved (017). A message can hold a skill chip. |
| 000, 001, 002, 003, 004, 011 | A face is a pastel disc with dark features. In the dark theme they are dark discs with a thin rim of light and features of light that glow, in one family with the app mark. In the light theme they are light discs with a thin rim in the colour of the hue and dark features, and a face has no glow. A change of the theme changes every avatar at once, with no motion. The glow is still. The app mark is not an avatar and does not change with the theme. Light is allowed for the app mark, the avatars (in the dark theme) and the working badge only. A chat with many avatars must scroll as smoothly as one with flat discs. |

| 009 | A routine has a schedule and uses the model of its agent. | A routine has a schedule or a watch. It can have its own model and effort. A late run gets the planned time and the start time. |
| 002, 010 | Import lists what it will make, and the user confirms. | A review screen with tick boxes, routines not ticked, "Not imported", and a checklist after the import (014). |
| 015 | The island shows faces and a count while agents work, and the first waiting request. | A detail card with one row for each working agent (place, what it does, time). The attention card shows the place and the kind of step, and the user can go through all waiting requests ("1 of N"). In the mode "always", a result card shows when a reply ends or a task or routine fails. |
| 005, 007, 013 | Nothing limits a chain of agent messages, the steps of a task, or repeated reads. | A message chain stops at depth 8. A task stops at 300 steps by default (a setting from 20 to 2000). The third read with the same target and the same result is refused. |
| 005, 003, 004 | Retry starts a new task at once. | Retry shows a note first when the earlier try ran steps that may have changed things. |
| 006 | A runtime shows as found or not found, and signed in or not. | Five states: Checking, Ready, Needs sign-in, Needs repair, Not installed. "Check again" changes nothing. "Repair" is the only action that changes the program. |
| 007 | Three permission levels. Full access needs no confirm. | A fourth level, "Read only", the strictest. Full access asks for a confirm. The action log says whether a file step read or wrote. |
| 004, 005 | A part ends as done, failed or cancelled. | A channel can ask for review. A part is then in review until the user accepts it or asks for changes. |
| 005, 009 | A turn that ends with no error is done. | A task from a part, a message of another agent, a routine or a workflow ends as Blocked when the agent says it could not do the work. A blocked run counts as failed for the pause of a routine. |
| 001, 003, 007, 008 | Search looks at place names only. An agent cannot search its past chats. | The search field also lists matching messages, and a click opens the message. An agent has the tool "search chats" while its memory is on. |
| 003, 005 | A failed row tells the reason, and the retry note. After a restart the notice has "Continue" only. | A failed row also tells how far the turn went (not sent, sent, started). If the request never reached the model, the notice has "Send again" in place of "Continue". |
| 005, 013 | A turn that shows nothing runs without end. | A turn with no sign of life for 10 minutes (the user can change this) is stopped and fails. A wait for the user and a running tool step do not count. The failed row also tells how far the turn went, next to the retry note. |
| 006 | A vendor program from a crashed run can stay. | The app ends its own leftover programs at start. A runtime with a hung check never delays a turn of another provider. |
| 008 | The agent saves memory at once. The only undo is the chat line. The agent can save any text. | A choice for each agent: save at once, or ask first with a tab for proposals. A history tab with undo. The memory tool refuses a text that looks like a secret. |
| 001, 021 | Pages: agents and chats, workflows, tasks, usage. | Also the Today page, with a badge on its button for the items that wait in "Needs you". |
| 000, 008, 016 | The texts say that an agent "learns". | One rule: ROBot does not train or change a model. An agent gets better through its instructions, memory, knowledge and the skills that the user saves. The memory page and the knowledge page show one muted line with this fact. |
| 004, 005 | A part has a label. The check of the lead nudges, asks or does nothing. The summary names blocked parts. | A part can have a done test. In the check the lead gives a verdict, "Met" or "Not met", to each part that ended as Done and that the user did not decide on. "Not met" can lead to a nudge. The summary also names a part that stays "Not met". The verdict is a field, not a state. |
| 005, 019 | The task view shows the prompt, the steps, the messages, the child tasks and the three times. | It also shows the done test and the verdict of a part, and a list of moments (given, started, ended, decided, judged, closed). The fields sync. |
| 002 | The agent profile lists no work. | The profile has a block "Recent work" with the last 20 tasks, their state in words, and the time since the last change. |
| 002, 009, 017 | Three templates: general assistant, code reviewer, researcher. | Five starters: Assistant, Briefer, Researcher, Reviewer, Organizer. A starter can also make a paused routine and skills for the new agent. |
| 002, 017 | Deleting an agent leaves a skill that was only for it. It is listed nowhere and counts in the limit of 100. | The delete removes the agent from the list of every skill. A skill that was only for it is deleted, and the confirm text says how many. |
| 000, 001, 011, 012, 015 | The desktop app is built for macOS, Windows and Linux. Search opens with Cmd or Ctrl+K. | The desktop app is for Macs with Apple silicon only. Search opens with Cmd+K. The phone app is for iOS and Android. A phone with no such Mac cannot be used. |
| 012, 010 | A computer client cannot open the workflows of a linked server. | It sees the workflows and their runs, runs and stops them, and answers approval steps. With the switch "Can create and change agents" it also edits them. The assistant and the workflow file stay on the server. |
| 000, 001, 011, 012, 013, 014, 015, 019 | One computer holds one set of data, and it is one server. | A computer can hold up to 5 profiles. A profile has its own data, accounts, settings, linked devices and sync pair, and it is the server that a phone pairs with. The window shows one profile. The rail has a profile button when there are 2 or more. A profile that is not open keeps working, and makes no notice on the computer. The first profile is the data that exists today. |
| 003, 004, 005, 012, 015 | A quiet turn shows "Working…" until the silent limit stops it. | After 90 seconds with no sign of life (or half the silent limit, when shorter), every place that shows the turn reads "No answer from <name> for <time>". The turn goes on. |
| 007, 013, 014 | Four permission levels. | A fifth level, "Ask when unsure", between "Ask for risky steps" and "Full access". The decision model checks risky steps against the words of the user. Hard steps always ask. |
| 018 | Every call of a tool of a connection is risky. | With the switch "Trust read-only marks" of a connection, a tool that the connection marks as read only runs with no card at "Ask for risky steps" and "Ask when unsure". |
| 005, 009 | Usage shows per agent and day only. | Each task keeps its tokens. The task view shows the total of a tree with a line for each agent. A routine can have a token limit for each run. |
| 008 | An agent saves facts only in its turns. Its memory is the same in every place. | A memory check can suggest facts after every 10 done turns. A channel note is read only in its channel. |
| 002, 004, 013 | Each agent has only its own instructions. | A handbook for every agent of a server, and instructions for each channel. |
| 002, 014, 017 | An agent file holds agents and routines. | It can also hold channels, skills (made off) and the handbook (not ticked on import). |
| 023, 000, 005, 013, 014 | No program on the computer can talk to ROBot. | An outside program that the user adds can read, send work, wait and stop through a helper over MCP. It cannot answer approvals or change anything else. |
| 001, 002, 011, 012, 013 | The filter of places looks at names only. The role field is a text box. The place list shows no role. | The filter of places also looks at the role line of agents. The role field is a label: a chip with "Remove" and a list to pick a role from or to add one. An agent row shows its role line as a badge, also on a linked computer and on the phone. An agent still has one role line. |
| 007 | A turn holds outside content only from its own steps, and the mark ends with the turn. A hit of "search chats" is not outside content. | A turn also holds it when an earlier turn that the agent still sees held it (chat, thread, fork copy, or any agent in a channel). A part holds it when the job came from an outside program or the lead read outside content first. A hit of "search chats" on a message that the user did not write is outside content. The header of the place shows "Holds outside content" with "Clear". A change of the app settings is a guarded step. Belongs to S62. |
| 010 | The user makes a workflow on the canvas or imports a file. | The menu of the Workflows page also has "New from a starter". The one starter, "TLA+ check", makes a workflow of six steps: an agent writes a TLA+ model of a spec, runs TLC on it, and explains what TLC finds. It needs Java and the TLA+ tools program in the workspace of the agent, and it downloads nothing. |
| 003 | Compact is a command of the user only. A thread has no title rule, no limit and no rule for the task queue. The code holds at most 10 queued messages for each agent. | Compact keeps the newest 2 turns and adds the line "Compacted". The app compacts by itself before a turn at 85 percent use, with a setting. A new thread is titled "New thread", then by its first message. An agent has at most 50 threads. The main thread cannot be archived or deleted. A thread with a running turn or a queue cannot be archived or deleted. All threads of an agent share one task queue, and a thread that waits says so. The message queue of a thread holds 10, with new text. The phone and a linked computer show the main thread only, find no message of another thread, and answer the cards of other threads in "Needs you". |
| 005 | Waiting tasks of an agent start in the order they were made. No limit on the waiting tasks of an agent, or on the agents that work at once. | The order is: "Run next" picks, normal sources, background sources (routine, workflow), then a memory check. "Run next" on a queued task. An agent has at most 20 queued tasks, with a rule for each source. At most N tasks run at once in a profile (1 to 8, default 4). A task that waits for the user or for a task that it gave out uses no slot, and takes one again at the front of the order. |
| 013 | General has neither setting. | General has "Compact long chats automatically" (on) and "Agents working at once" (4). |
| 019 | Messages: direct chats and channels. | Messages: direct chats with their threads, channels, and the rows "Compacted". |
| 000, 003, 011, 012 | A picture from the web in a Markdown text loads when the text shows. | It shows as a box with a button "Load image". It loads when the user presses the button, and only that picture. |
| 007 | Risky steps: delete outside the workspace, network send, install, `sudo`, the data folder, connection tools, secret requests. A web page fetch never asks. | Also a change to a control place and a fetch of a local address. A fetch of a link-local or metadata address is refused. A turn that read a place with keys or logins asks before a step that sends data out, also when an Allow rule matches. |
| 018 | A connection gives its tools to agents as it offers them. | A new tool, or a tool with a changed description, is held until the user accepts it. |
| 003, 005 | The user starts new work with an agent by writing a message. | A chat can be handed over to another agent, with a brief. A task can have the source "Handover". |
| 017, 005, 008, 016 | A skill is written by hand, or taught in the browser. | A skill can also be made from a task that is done, an article, or a memory item. |
| 004, 011, 015, 021, 024 | A question of a member in a part goes to the user. | When the channel setting "The lead answers questions" is on (the default), the lead gets the question first. It answers with a reason, or passes it to the user. The user can answer at any time. An approval never goes to the lead. A question from a turn with outside content, and the fourth question of a part, go to the user at once. After 2 minutes the question passes to the user. |
| 025, 004, 007 | Two agents can use one folder, and nothing stops one from writing over the other. | A file that a task changed in a shared folder is claimed until the task ends or is in review. A file step of another agent on it is refused with the name of the holder. Each turn in a shared folder gets a note with the claims of the others. |
| 025, 004, 005, 019 | A part always works in the workspace of its member. | With the channel setting "Own copies for parts" on, the lead can give a part its own copy of a Git repository on a new branch. The app commits the changes to the branch at the end of the part, removes the copy at the end of the request, and never merges or pushes. |
| 013, 026, 003, 006, 007, 015 | Nothing cuts the repeated work of an agent. | A settings section "Token savings" with three switches, off at first: "Check with edit", "Set big results aside", "Compact at finished steps". A table in 026 says which agents each one reaches: all three for an API account, all three for pi (the first at "Full access" only), and only the big results of the tools of the app for Claude Code, Codex, opencode and Muse Code. A task shows a savings line. A compact in the middle of a turn is not the end of the turn. A set-aside result keeps the mark of outside content. A short context is never compacted by a saving, and the tokens of a compact count in the task. |
| 006, 002 | A turn that meets a usage limit fails with the reason and the reset time. | An agent can have a backup model. A turn that meets a limit goes on with it, and the main model is held until the reset time. |
| 005, 003, 013 | A turn that ends with open steps ends the task. | With "Keep going on open steps" on (the default), an agent whose runtime reports a list of steps is asked to go on, up to 8 times for one request. |
| 006, 002, 010 | Effort levels are Low to Max. | None, Minimal and Ultra appear for a model that lists them. |
| 006 | The picker lists the models as the provider gives them. | Newest first, older models in a fold, a "New" tag for 7 days, models that the user can hide, and a context size and an output limit for a custom model. |

| 020, 007 | A saved secret is for web requests. | Saved logins also exist, for the browser of an agent. The model never sees them. |
| 027, 003, 011, 013 | The user types every message. | Dictate in the message box, read aloud, and voice chat on the phone. Recognition runs on the device. |
| 015, 012, 013 | A linked phone gets a notice at once. | The server holds notices back while the user works at the computer. A menu bar item, a choice of sound, and a quit that asks while work runs. |
| 001, 003, 011 | Sections are one level deep. A place can be marked as read only. There is no find in a chat. | Sections inside sections, pinned places, "Mark as unread", and Cmd+F in a chat. |
| 011, 003 | The phone has no share target. Images of a message show one by one. | A share sheet target, a face in notices, a stack of images, a thinking sheet. Pasted images show a preview. |
| 007, 008, 022, 023 | The tool "search chats" uses the first 6 words and needs every word. It gives hits newest first, each with a piece of 300 characters, and the agent cannot read more of a chat. | The tool takes 12 words and finds a message that holds at least half of them. Hits with the most matching words come first, and each hit has the count and a reference. A second tool, "read chat", gives up to 5 messages before and 5 after a message, and one line for each tool step between them, with its kind and result and no text. A message in its result follows the rules of outside content. Message search of the user (001) does not change. |
| 028, 000, 014 | The app sends no conversation text to a chat service. | A Teams link, off at first, reads one Microsoft Teams chat in a Teams page where the user signed in by hand. It gives the calls of allowed senders to one agent or one channel, and writes the answers in the same chat. |
| 028, 007, 003, 005 | Outside content comes from pages, connections, other agents, routines and outside programs. | A message from Teams is outside content and holds the program mark. It shows with "From Teams", makes a task with the source "Teams", never joins a running turn, and never answers a card. |
| 028, 013, 015, 019, 021, 022, 002 | Settings have no part for a chat service. | A settings part "Teams", a notification "Teams link needs you", a Today row, and a link that belongs to one computer and one profile. It is not in sync or in an export. An agent cannot change it. |
| 029, 012 | The org chart is read-only on every device. | The computer, and a linked computer with "Can create and change agents", change members, the lead and the parent channel on the chart, by menu or by drag, with Undo for 10 seconds. The phone stays read-only. |
| 004, 029, 030 | Channels are one level. Every channel node hangs from the root. | A channel can have a parent channel, at most 3 levels. A sub-channel node sits under its parent on the chart and in the phone list. |
| 007, 030 | Any agent can send a message to any other agent. | Same by default. With the hand-off rule "Along the channels", "send message" works only along the channels, and "list agents" lists only the agents on the path. |
| 004, 030 | A question that the lead passes goes to the user. | Same by default. With "Ask up the line" on, a pass that is not "Only the user can choose" goes to the higher leads and the main agent first, at most 3 agents and 5 minutes. |
| 017, 018, 030 | The agents of a skill or a connection are "All agents" or a list of agents. | The list can also hold channels. A channel gives the skill or connection to its members and to the members of its lower channels. |
| 005, 006, 030 | A channel has no limit of its own. | A channel can have a daily token limit. At the limit, new tasks of the channel and its lower channels end as Blocked. |
| 003, 011, 013 | Finished tool steps always show as one card each. | The switch "Show tool steps" (on at first) can be turned off. | 000, 001, 003, 011 | The working dot of a place, of a collapsed header and on the phone is still while the work runs. | 002 | The spec said of the role line "the model gets it as before". A model reads the role line in three places only: the check of the lead (004), the fast pick (004) and the answer of the settings tool. ## Decided against

- Using ACP (Agent Client Protocol) as the way to reach the savings of 026 in vendor programs.
  Decided against on 2026-11-03. ACP carries events, permission requests, usage and a compact
  command. It does not let the app change what the model of a program reads. The savings in a
  vendor program come from the settings and the add-ons of that program. ACP may still be a way to
  join the adapters of the programs; that is a question for 006, not for 026. See
  `docs/token-savings-research.md`.
- Reading a long log with a cheaper model (a fourth saving). Not in S77 (026). It sends logs to
  a second model, so it needs a model choice and a new exception in 000 and 014. Open for a later
  change.

- Temporary helpers: an agent that gives parts of a request to short-lived helpers and joins their
  results. Decided against on 2026-11-03. Vendor programs already start their own helpers (015,
  "another agent"), and a channel with a lead splits a job between agents that the user can see.
  Open for a later change if agents that use the tools of the app need it.
- A password, a PIN or a lock for a profile. Not in the first version (022). A profile keeps work
  apart and does not lock anyone out; a separate user account of the system is the wall. Open for
  a later change.
- A rule that computer use (007) never looks at a window of ROBot. Open: with profiles, an agent of
  one profile with computer use can look at the window that shows another profile. 022 says this
  in "What is shared". 007 may need a rule later.
- The app writes an agent setup from a text that describes a job, and the user then reviews it and
  presses a "Hire" button. Decided against on 2026-11-02. A starter (S53) is the way to begin a
  job. The words "agent", "member" and "New agent" stay in the interface.
- A new state for the review of the lead. The state "in review" belongs to the review of the user
  (S37). The lead gives a verdict, which is a field. So a restart, a stop, or a blocked lead needs
  no rule for a part that waits for the lead.
- A coaching card, with which an agent proposes a change of its own instructions after the user
  corrects it, is not in this list. It is open for a later change.
- Auto-answers to the question of an agent. Decided against on 2026-11-04. "Keep going" (005) decides
  from the list of steps of the runtime and never from the words of a reply. The go-on message does
  not answer a question of the agent, and it tells the agent to ask with a question card. The app
  answers a question of the agent for the user in no case.
- A trigger from a chat service (Discord, Slack and so on) for a workflow. Not in this version
  (010). It needs a bot account and a link to the service. Open for a later change. The Teams link
  (028) is a different thing: it gives work to an agent or a channel, not to a workflow.
- A saved card number, address or one-time code that an agent types into a page. Decided against on
  2026-11-04. The agent never types a card number or a code (007, 020). Saved logins (020) are
  the only sign-in data that the browser fills.
- A palette file from another tool as a theme. Not in this version (013). ROBot has two themes and
  a text size.
- Chat services other than Microsoft Teams (028), a hosted marketplace of agents and skills, and
  share links for it. Not in this version. Agent files and workflow files (002, 010) are the way
  to share a setup.
- An approval, a question card or a command ("stop", "retry") answered from a chat service.
  Decided against on 2026-11-04 (028). A message from Teams is outside content and holds the
  program mark. The user answers a card in the app or on a linked device.
- Search of tool output and of tool arguments in "search chats" and "read chat". Not in S78. Output
  and commands can hold secrets, web text and file text, and the action log (007) already keeps the
  kind, the target and the result of a step. S78 shows only the kind and the result of a step.
  Open for a later change if the plan of `docs/memory-evaluation.md` shows that the group "Failed
  attempt" needs more.
