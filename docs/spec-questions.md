A `branch` on a connection that leaves a step that is not a condition is ignored. |

| 006, 003, 008 | How does the chat go to Claude Code, so that the model can read most of it from its cache? The chat as one block of text was never read from the cache, because it changed in the middle at each turn. | Each message is its own block, in a fixed order, so the blocks of a turn begin with the blocks of the turn before. One fixed first block says how to read them. The notes of the app for a message (the memory items that relate to it) are kept with that message in the database, and go with it again in each later turn. They are not in the instructions, which come first in the request and would change at each message. The chat shows the notes nowhere. When the history is over 60 000 characters, the oldest messages go in steps of eight blocks, with a mark where they were, so that the start stays the same for several turns. Measured on Claude Code 2.1.316 with the code of the app: four turns, one run for each way, no tool calls. The cache write of turn 4 fell from 14,308 to 5,628 tokens, the cache read of turn 4 rose from 11,171 to 19,914 tokens, and the cost that the program reports for turn 4 fell from $0.0584 to $0.0245. The input tokens on the usage page do not fall, because they count cache reads. Codex, Muse Code and pi still get the text, and the memory in their instructions. |
