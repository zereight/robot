implementer made to continue. A spec author answers by changing the spec.

| 003 | How long can the queue be, and how long can a message be? | Up to 10 queued messages and 100,000 characters per message. More gives a plain error. |
| 003 | Does Stop also cancel the queue? | No. Stop ends the current turn; the next queued message is then sent. |
| 003 | What does "edit" on the user's last message do? | It saves the new text, removes the replies after it, and asks the agent again. Only when the agent is not working. |
| 003 | Which failed turns can be retried? | Only the last reply, when it failed. Retry replaces the failed row. |
| 003 | "Stored as each part arrives": how often? | The partial reply is written at most every 500 ms and when the turn ends. A turn still marked as streaming at start-up becomes "stopped". |
| 003 | Does Markdown allow raw HTML, and where do links and images go? | Raw HTML shows as plain text. Links open in the system browser (http, https, mailto only). Images load only from https addresses. |
| 003 | Attach (flow 4) and Approve (flow 6) | Attach comes in slice S7. Approve needs agent tools (007), which are not in M1. |
| 003 | What makes a chat unread in the place list? | An agent reply that ends while the chat is not open. Opening the chat clears the count. |
| 000 | Which parts of the window move, and how? | Dialogs and settings fade and rise in (200 ms) and fade out (120 ms). New messages rise in; history does not move. The activity panel slides, sections fold, badges and the working dot pop in, the send and stop icons turn in, hover actions fade. Buttons press in a little. Every motion is under 300 ms; only the "Working…" line loops (003). Reduce motion sets every duration to 0. |
| 003 | How does the quoted message "flash"? | It takes the selected colour at once and fades back after about 1.3 s. Each fade is under 300 ms. |
| 000 | How is the desktop app delivered, signed and updated? | Draft GitHub releases from a version tag, for macOS (arm64, x64), Windows x64 and Linux x64, each tested end to end as a packaged app. Ad-hoc signed on macOS until a Developer ID exists; automatic updates wait for signing. See docs/release.md. |
| 000 | What is the app mark? | A white robot face with an antenna on the accent colour (#4f66d9), flat, in a rounded square. |
| 000 | What does the first start guide show, and can the user leave it? | Three steps in one box: language and theme, one model account, one new agent. Every step can be skipped, and "Skip the guide" ends it at once. Escape and a click outside do not close it. It shows once: a data folder that already has an agent or an account counts as done. |
| 006 | Which numbers does the usage page show, and what about cost? | Finished replies, input tokens and output tokens, per agent and per local day, for the last 7 or 30 days. Stopped and failed replies do not count. No cost is shown: the providers in M1 report tokens only. Plan limits come with agent runtimes, which are not in M1. |
| 003 | How many files, how large, and where do they go? | Up to 10 files per message, 20 MB each. A copy goes to the `attachments` folder of the agent workspace; a taken name gets a number. The model sees the file path in the text. Images are not sent to the model as pictures in M1. |
| 003 | Can a message be only files? | Yes. A message needs text or at least one file. |
| 014 | What does the export archive hold, and what is hidden? | A zip with the database, the attachments per agent, a readme and a format version. Text in chats that looks like a key or token, or equals a stored key, becomes "[redacted]". Attached files are copied as they are. |
| 014 | When can data be imported? | Only into an app with no agents and no accounts, and only from the same data version. Agents join this computer's server. Accounts come back as "Not connected". |
| 005 | Is every chat reply a task? | Yes. Each agent turn in a direct chat is one task with source "chat". The prompt is the last message of the user. |
| 005 | What does Retry do for a chat task? | A failed reply is asked again. A stopped one is sent again as a new message. Either way, the new task links to the old one. |
| 005 | Does a chat turn wait for another task of the same agent? | Yes. One agent runs one task at a time, across chats and channels. The waiting task shows as queued. |
| 005 | How many tasks does the page list? | The newest 500 of the server. Filters and search work on this list. |
| 004 | How does a lead split a job? | The lead gets rules in its system text and answers with one JSON object (plan sentence and up to 8 parts with member, label and prompt). A reply that does not parse, or names no member, is an ordinary answer. The app then shows the plan message, starts the parts at once, and asks the lead for one summary when all parts have ended, also when some failed. |
| 004 | Do parts run at the same time? | Parts of different members run together. Parts of one member wait in its queue (005). |
| 004 | What does the user see when no lead exists and there is no mention? | The job shows with a row of member buttons. The user picks one; that member answers. |
| 004 | What happens with several mentions? | Each mentioned member answers. The lead does not read the job. |
| 004 | Can a lead be removed while it works? | No. A member with an active part or job cannot be removed until it ends or the user stops it. Removing the lead clears the lead. |
| 004 | Where is the channel section button? | A plus button on the Channels section header, like the one for agents. |
| 004 | What does "Stop" do in a channel? | The send button turns into Stop while work runs. It stops every job and part of the channel. A step has its own stop button. |
| 007 | Which tools does an agent have in this version? | Files (list, read, write, search), shell command, web fetch (GET), ask the user, save memory. The browser tool comes later. |
| 007 | Which steps are "risky"? | `sudo`, installing software, sending data over the network, piping into a shell, and deleting outside the workspace. Reading or writing outside the workspace also asks. |
| 007 | Do channels use tools? | Not yet. A tool call in a channel fails with a note. |
| 007 | What happens to a card that waits when the turn stops? | The step is marked Failed and the card goes away. |
| 008 | How does an agent choose which memory items to read? | Items that share words with the message, newest first, at most 20 items and 4000 characters. With fewer than 6 items, all are read. |
| 008 | Where does the user change the permission level and memory? | In the agent profile dialog, with the memory list, search, add, edit and delete. |
| 007 | Where is the browser kept, and who holds the controls? | One window per agent, with its own saved session. The chat header shows "Take control" and "Give back". Steps of the agent wait while the user holds the controls. Stop closes the window at once. |
| 007 | Can agents use tools in channels? | Yes, in replies of members. The lead's plan and summary use no tools. Cards show in the channel. |
| 009 | Which reply counts as the missed run on wake? | The newest due run starts if it is under 12 hours late. Older due runs show as Missed. |
| 009 | Where does a routine post when the place is a channel? | The agent answers the prompt in the channel. The agent must be a member. |
| 009 | Does a paused routine count the pause as missed? | No. Resuming or editing a routine starts its checks from that moment. |
| 010 | What does a prompt in a workflow step see? | `{{input}}` is the joined result of the steps before. `{{trigger}}` is the text that started the run. Without `{{input}}`, the input is added at the end of the prompt. |
| 010 | How does a condition step choose a branch? | It tests whether the input contains a text, ignoring case. Yes and No are separate outputs. A step with no active input is Skipped. |
| 010 | What do the "post message" and "approval" steps do? | Post puts a note in a channel. Approval waits for the user to approve or reject in the editor. Reject fails the run. |
| 010 | Which agent chat shows the prompt of a workflow step? | The chat of that agent, as a message. The task has the source Workflow. |
| 015 | When does a system notification show? | Only while no window of the app has the focus. The do-not-disturb of the system is respected by the system. |
| 015 | What is a "mention in a channel"? | A finished reply of an agent that holds `@you` or `@user` as a word. |
| 015 | Which place does a failed task open? | The channel for a channel task, otherwise the agent chat. A routine failure counts as "routine failed". |
| 015 | What is the default of the island, and where is it set? | "Always", on macOS only, in Settings > Notifications. Other choices: only for attention, off. |
| 015 | What shows on the island for a question? | The question and "Open app". Only approvals have Allow and Deny on the island. |
| 015 | How is a mute chosen? | One select per server and per channel in Settings > Notifications: not muted, 1 hour, 8 hours, 1 day, until turned back on. |
| 006 | Which programs run as agent runtimes, and how does the app run them? | Claude Code through `claude -p` with the stream-JSON input and output, and Codex through `codex exec --json`. Both are the vendor's own programs and use the user's own sign-in. The app never reads or stores their tokens. |
| 006 | Where does the app find the program, and when does it download? | Order: the copy that the app downloaded, then a path in `ROBOT_CLAUDE_BIN` or `ROBOT_CODEX_BIN` (which stops the search of the computer), then the PATH and the usual folders. "Download" fetches the newest release into the data folder. The file must match the SHA-256 that the vendor publishes, as the vendor's own installer demands; a wrong file is deleted. A copy of the data folder on another computer finds the file broken and offers the download again. |
| 006 | What counts as connected for a subscription account? | The program is on the computer, and its sign-in is a subscription (Claude plan or ChatGPT plan). A program that is signed in with an API key does not count; the form tells the user to sign in again. The state is read again when a message is sent, if the last look is older than 60 s. |
| 006 | What does "Disconnect" do to a subscription account? | It switches the account off in the app only. The vendor program stays signed in, because other tools of the user use it. "Connect again" checks the program and switches the account on. After an import the account is off. |
| 006 | How does the app keep the subscription as the payer? | It removes API key, token, gateway and cloud variables (for example `ANTHROPIC_API_KEY`, `OPENAI_API_KEY`) from the environment of the program, does not use the `--bare` mode (which ignores the sign-in), and starts Claude Code with no user settings, hooks or MCP servers. |
| 006 | Which models do the runtimes offer? | The programs have no list that the app can read. Claude Code offers the names Opus, Sonnet and Haiku, which always mean the newest model of that family; the first two take an effort level. Codex offers "Default", which lets Codex choose the model for the plan. The user cannot type another model id for a runtime in this version. |
| 006 | Does a runtime keep a session between turns? | No. Each turn starts a new program run and gets the chat so far as text (the newest 60 000 characters of history, and the new message). Sessions of the program are not saved, so the history of the user's own Claude Code is not touched. |
| 006 | What does the usage page show for a subscription? | The tokens of each reply, as for API accounts. The plan limits (5-hour and weekly windows, with the reset time) show in Settings > Providers under the account, from the last report of the vendor. When the vendor refuses a turn for the limit, the reply fails with the reset time. |
| 007 | How do the permission levels reach Claude Code? | The program asks the app before each step it does not do on its own, and the app answers by the level, in the same cards as the own tools: "Ask for everything" asks for every such step; "Ask for risky steps" asks only when the rules of 007 call the step risky (shell commands by the risk list, files outside the workspace); "Full access" asks nothing. "Always allow" is kept per agent. The question tool of Claude Code is off; the agent asks in its reply. |
| 007 | How do the permission levels reach Codex? | A non-interactive Codex run cannot ask. The level becomes the sandbox of the run: "Ask for everything" is read-only (the agent can look but not change), "Ask for risky steps" is write inside the workspace only (no network, no outside writes), "Full access" has no limit. Approval cards for Codex need its app-server protocol, which is marked experimental by the vendor; they come later. |
| 008 | Can a runtime agent save memory? | It reads the memory items in its instructions, but it has no tool to save one in this version. |
| 004 | Do runtime agents work in channels? | Yes, as members. The lead's plan and summary turns run with no tools, which for Claude Code removes its tools, and for Codex makes the run read-only. |
| 006 | How does Muse Code run, and how does the user sign in? | `muse exec --json` with the prompt in a temporary file and the workspace of the agent. The app sets `MUSE_NO_AUTO_UPDATE=1`, so the launcher does not update itself during a turn, and passes the flags that keep the user's session log and the files of other agent tools out. Sign-in is `muse login` (device code): the app shows the page and the code from the program and opens the page when its host is `meta.com`, `facebook.com` or `meta.ai` over https. The state and the plan limits come from `muse usage --json`, which makes no model turn. A key in `META_API_KEY` is removed from the environment; a key stored in the program is shown as "not a subscription". The app does not download Muse Code: the program is the vendor's launcher, which updates itself, and the app has no published checksum for it. |
| 007 | How do the permission levels reach Muse Code? | A headless run cannot ask. "Ask for everything" turns off write and shell. "Ask for risky steps" keeps the sandbox of the program on. "Full access" turns off the approval and the sandbox. A run without tools turns off write, shell and web tools. |
| 006 | How does pi run, and what counts as signed in? | `pi -p --mode json --no-session`, with the prompt on stdin, and without context files, skills, prompt templates and MCP of the user. pi has no single account: each of its models has its own login or key, which the user sets up inside pi. So the app does not sign in for pi; it offers the models that `pi --list-models` shows, and "signed in" means that the list is not empty. The model id is `provider/model`. The environment of pi is left as it is, because pi can use keys from it; so pi is the one runtime that can bill an API key, and the form says so. The app does not download pi: it is an npm package. |
| 007 | How do the permission levels reach pi? | pi does not ask before a step. The level becomes the list of tools: "Ask for everything" gives read, grep, find, ls; "Ask for risky steps" adds edit and write but no shell; "Full access" gives all tools. A run without tools has none. |
| 006 | Which models do Muse Code and pi offer? | Muse Code offers "Default", which is the model that the program chooses for the account. pi offers the list of its own models. |
| 002 | Can the app suggest a random name when the user makes an agent? The spec does not say. | Yes. The new agent form has a dice button next to the name field. Each press puts a random name from a list of 24 (English and Korean lists in the catalogues) in the field. It never gives the name in the field, nor a name of an active or archived agent on the server (the rule of 002 ignores case). When all 24 are taken, it adds a number ("Nova 2"). The field is not filled when the form opens, the other fields stay as they are, and the user can still type any name. The edit form has no button. |
| 006 | Which effort levels does a pi model offer? | The ones that pi tells for that model, from the lowest: minimal, low, medium, high, xhigh, max. "Off" is not a level, because "Default" already means that the app sets none. A model that does not think has none. When pi cannot tell the levels, a model that thinks offers low, medium and high. A level that the app does not know is not offered. The choice stays with the user: "Default" lets pi choose. |
| 016 | How does the header of an article file look, and what is the summary of a file with no header? | A header between two `---` lines holds `title:`, `summary:` and one `source:` line for each source; other header lines are kept as they are. A header that names no title and no summary counts as no header. For such a file the summary is its first line that is not empty, as it is: a heading mark stays. A summary that the app takes from a first line is cut at 160 characters. |
| 016 | How is a source file named, and what is the first line of a page? | A file source keeps its name; a taken name gets a number. A page is named from its address. The first line of a page is `Fetched from <address>`. The copy is read-only for other programs. |
| 016 | Which tools does an agent get, and how does it link? | `read_article`, `write_article` (whole body; optional links and sources), `delete_article` and `add_source` (a file in the workspace, or an address). A link that the body does not name is added as a last line `See also: [[Title]]`. |
| 016 | Does the card of the first save offer "Always allow"? | No. It has Allow and Deny only, and it asks again when the Knowledge folder is missing again. |
| 016 | After the user sets a root in Settings, is a workspace under the built-in root still in the default workspace folder? | Yes. A folder is in the default workspace folder when it is under the built-in root or under the root from Settings. The root folder itself is not "in" itself, so an agent that works in the root has a chosen workspace. |
| 016 | What does the list of changes show after an undo, and what if the article cannot be found? | The change that was undone shows "Undone" and has no undo control; the undo is a new change with its own control. Undo finds the article by its file, then by its title. An undone edit whose article is gone comes back as an article; an undone add whose article is gone fails with a plain error, and so does an undone delete whose title is taken. |
| 016 | Which of two files with one title is shown, and which files count as articles? | The file that the app knew first is shown, then the file whose name comes first. Only files with the ending `.md` count. A Markdown file in the `sources` folder is a source, not an article. |
| 016 | When is "Check knowledge" on, and what if the message is too long? | It is on when knowledge is on and there is at least one article. A message that would be longer than a chat message ends with a line that says how many findings are not in it. |
| 016 | What are the details of the contents list? | One line is `- title: summary`. A whole list is sorted by title. The line about the articles that are not in a cut list counts inside the 100 lines and 6,000 characters. A line that does not fit is left out, and a summary of more than 160 characters is cut in the list. |
| 016 | Does the block on the file tools cover shell commands? | No. It covers the file tools: list, read, write and search. A search leaves out the sources, and the articles while knowledge is on. A shell command in the folder is not checked. |
| 000 | The spec says every motion is under 300 ms. Agent faces could turn their eyes toward the pointer, and that motion has no end. Is it allowed? | No. Faces react with one-shot motions only (blink, hop, shake), each under 300 ms. A spec author may allow the eye motion later. |
| 013 | The app uses the system font. A bundled font such as Inter or Pretendard has the SIL Open Font License, which `CLEANROOM.md` does not list. May a font under that license ship? | No. The system font stays until a spec author decides. |
| 001 | The activity panel of a direct chat showed one muted line until tasks existed. Tasks exist now. | 004 | The member list of the channel form can be long. Can the user search it? The spec does not say. | Yes. A search field is above the list, in the new channel form and in channel settings. | 006, 003, 008 | How does the chat go to Claude Code, so that the model can read most of it from its cache? The chat as one block of text was never read from the cache, because it changed in the middle at each turn. | Each message is its own block, in a fixed order, so the blocks of a turn begin with the blocks of the turn before. One fixed first block says how to read them. The notes of the app for a message (the memory items that relate to it) are kept with that message in the database, and go with it again in each later turn. They are not in the instructions, which come first in the request and would change at each message. The chat shows the notes nowhere. When the history is over 60 000 characters, the oldest messages go in steps of eight blocks, with a mark where they were, so that the start stays the same for several turns. Measured on Claude Code 2.1.316 with the code of the app: four turns, one run for each way, no tool calls. The cache write of turn 4 fell from 14,308 to 5,628 tokens, the cache read of turn 4 rose from 11,171 to 19,914 tokens, and the cost that the program reports for turn 4 fell from $0.0584 to $0.0245. The input tokens on the usage page do not fall, because they count cache reads. Codex, Muse Code and pi still get the text, and the memory in their instructions. |
| 006 | Should a runtime also keep a session between turns? Should Codex, Muse Code and pi get blocks or sessions? In a test, the cache write of turns 3 and 4 with a saved session was 2,182 tokens, against 5,628 with blocks. A session is a file in the folder of the program. It needs rules for edit, retry, fork, a change of model, a lost session and the context meter. The other runtimes were not measured. Their help texts show `--session-id` for Muse Code `exec`, and `--session-id`, `--session` and `--fork` for pi. The Codex on the test computer is too old to tell. | No sessions. Nothing changes until a spec author decides and the other runtimes are measured. |
