| 012 | Which well-known protocols protect the pairing and the later connections? | Pairing: SPAKE2 as in RFC 9382 (curve P-256, SHA-256, HKDF, HMAC key confirmation), from `@noble/curves` (MIT), with the 6-digit code stretched by scrypt (N = 2^15) into the password. A wrong code never shows the code, and 5 wrong tries end the code. Linked connections: Noise `IK` with `25519_AESGCM_SHA256` (Noise specification, revision 34): each side knows the public key of the other from the pairing, so the first message already hides the device. The app checks both against the published test vectors (RFC 9382; the public Noise vector set). AES-GCM is chosen over ChaCha20-Poly1305 because the test runtime of the project does not have the second one. The transport is a web socket; the app seals every message itself, so the link is safe also on a network without TLS. |
| 012 | Where does a device keep its identity, and what does the device id show? | The identity is an X25519 key pair; the private key is in the keychain (the same store as provider keys). The device id is the first 32 hex digits of the SHA-256 of the public key. If the keychain has no key (new computer, or the user cleared it), the app makes a new key and removes all links, because the old links cannot work any more; the user pairs again. |

| 019, 016 | A message that was made on one computer holds a card of a knowledge tool (what the agent read or wrote, or a question about an article that the user edited last). The article does not sync. What does the other computer show? | The card shows its line and, for a question, the old and the new text, because they are part of the message. The other computer shows no undo and no link to an article. A reply to the question goes to the computer where the reply runs, as an approval does. |
| 019, 016 | Does the knowledge switch of an agent sync? | No. It is a setting of the computer, like the memory switch. A synced agent has the switch on, and no article. |
| 014, 012, 019 | Does the export keep the names that chats and agents show for linked computers ("sent from", "last changed by")? | Yes. They are names in the data, not keys or addresses. The links, their keys and addresses, the sync records and the "runs on" computer of a routine or workflow stay out. |
| 012, 015 | A workflow of a linked server shows a notice (notify step). A client has no Workflows page. What does a click on the notice open? | The window opens the Workflows page of the linked server. It shows "Open this on <server name>." |
| 019, 010 | How large may the canvas notes of a workflow be in a change that comes by sync? | The limits of the workflow: at most 50 notes of 2,000 characters each, of the four tones. A change with a larger list, an unknown tone or an unknown field is refused as a bad change. |
| 019, 016, 014 | The card of a question about an article holds the old and the new text of the article. A message with this card syncs, so this text and the titles in the cards of knowledge tools reach the other computer, although the knowledge itself does not sync. Is this wanted? | Yes, for now: the other computer needs the text to show the question and to take the answer. Sync checks the card strictly (the old and the new text up to 200,000 characters each). The spec author may decide to send only the title. |
